# Модуль `collab_stage.py` — Коллаборативная фильтрация и вкусовые архетипы

## 1. Назначение модуля
Модуль реализует этап коллаборативной фильтрации конвейера `build_index`:
1. **`step_collab_favs`**: Построение графа совместных добавлений в избранное (co-favorited graph) между постами с математическим взвешиванием активности пользователей.
2. **`step_taste_archetypes`**: Кластеризация профилей пользователей в 64 вкусовых архетипа с помощью сферического `MiniBatchKMeans` и сохранение репрезентативных постов для холодного старта рекомендательной системы.

---

## 2. Граф совместного избранного (`step_collab_favs`)

### Математическая модель
Каждому пользователю $u$ с числом постов в избранном $|F_u|$ сопоставляется вес обратной длины истории:
$$M_{u, p} = \frac{1}{|F_u|^{0.25}}$$
Вес ребра совместного избранного между постами $a$ и $b$ рассчитывается как скалярное произведение столбцов матрицы $M$:
$$W(a, b) = (M^T M)_{a, b} = \sum_{u \in U_a \cap U_b} \frac{1}{\sqrt{|F_u|}}$$
Такая нормализация гарантирует, что пользователи-«коллекционеры» (добавившие тысячи постов) не создают ложных шумных связей между случайными изображениями, в то время как совпадение в избранном избирательных пользователей даёт мощный сигнал семантического родства.

### Архитектурная оптимизация памяти (Chunked Row Projection)
Прямое умножение матрицы $M^T M$ для $2.95\text{M}$ постов порождает более $5.1$ млрд ненулевых элементов ($> 80$ ГБ ОЗУ).
Для сохранения строгого лимита RAM $< 500$ МБ реализована **построчная чанкованная проекция**:
1. Матрица $M^T$ разрезается на горизонтальные блоки по $5\,000$ постов:
   $$C_{\text{chunk}} = M^T[\text{start}:\text{end}, :] \times M$$
2. Блок занимает всего $\sim 50$ МБ RAM. Внутри него:
   - Берутся только элементы строго выше главной диагонали ($a < b$).
   - Мгновенно отсекаются шумовые связи с весом ниже порога (`cofav_min_weight = 0.5`).
   - Для каждого поста сохраняются не более `cofav_max_edges_per_post = 64` сильнейших соседей.
3. Отобранные рёбра сбрасываются в `post_cofav.parquet` потоковым `pyarrow.parquet.ParquetWriter`.

## 3. Вкусовые архетипы (`step_taste_archetypes`)

### Потоковое накопление пользовательских эмбеддингов
Вместо удержания миллионов 128-мерных векторов постов в словаре Python:
1. Выделяется компактная матрица сумм размером $|U| \times 128$ ($44\,367 \times 128$ float32 $\approx \mathbf{22.7\text{ МБ}}$).
2. Датасет `post2vec.parquet` считывается потоковыми батчами по $50\,000$ строк через `iter_batches()`.
3. Векторы постов накапливаются в строках соответствующих пользователей.
4. Полученные пользовательские векторы проецируются на единичную сферу $S^{127}$ ($L_2$-нормализация).

### Кластеризация и топ-посты
1. Сферический `MiniBatchKMeans(n_clusters=64)` с динамически вычисляемым `batch_size` (от 3072 до 8192 в зависимости от числа активных пользователей) кластеризует вкусы пользователей в 64 компактных центроида.
2. Центроиды сохраняются в `taste_centroids.npy` (нормализованы к $\|c_k\|_2 = 1$).
3. Для каждого центроида через индекс `post2vec_sq8.index` отбираются ближайшие по косинусному расстоянию посты (`taste-archetypes-top-posts`, по умолчанию 500).
4. Результат сохраняется в `taste_archetypes.parquet`.

---

## 4. Входные и выходные артефакты

### Входные данные:
- `user_favorites.csv`: столбцы `user_id` и `favorites` (в формате PostgreSQL массива, например `"{1,2,3}"`).
- `post2vec.parquet`: эмбеддинги постов.
- `post2vec_sq8.index` + `post2vec_faiss_ids.parquet`: квантованный индекс FAISS.

### Выходные данные:
- `features/post_cofav.parquet`: рёбра графа `(a_post_id: int64, b_post_id: int64, weight: float32)`.
- `features/taste_centroids.npy`: массив центроидов `float32` размерности $(64, 128)$.
- `features/taste_archetypes.parquet`: таблица `(archetype_id: int32, post_id: int64, rank: int32, score: float32)`.
