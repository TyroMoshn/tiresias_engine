# Модуль `pools_stage.py` (Техническая документация)

## 1. Назначение и Архитектурная роль
Модуль `pools_stage.py` отвечает за обработку структурированных пользовательских подборок — пулов (альбомов, глав комиксов, серий и тематических коллекций). Пулы содержат концентрированный семантический контекст более высокого порядка, чем обычные одиночные посты.

Модуль решает задачи:
1. Парсинг и шардирование пулов (`step_pools_parse`).
2. Фильтрация шумовых коллекций на основе информационной энтропии Шеннона (`step_pools_entropy`).
3. Построение взвешенного графа схожести постов на основе общих пулов (`step_pool_edges`).
4. Формирование Memory-Mapped вектора участия постов в пулах (`step_post_in_pools_count`).
5. Извлечение графа совместной встречаемости тегов на уровне пулов (`step_pool_tag_co`).

## 2. Фильтрация и парсинг (`step_pools_parse`)
- Парсинг поля `post_ids` формата PostgreSQL array (`"{123,456,789}"`) с удалением мусорных нечисловых токенов и дедупликацией.
- Фильтрация:
  - `is_active == 't'` (только активные пулы).
  - Размер $n \in [\text{pool\_min\_size}, \text{pool\_max\_size}]$ (по умолчанию $3 \le n \le 200$). Пулы размером менее 3 элементов не несут контекста со-встречаемости, а гигантские пулы размывают семантику.
- Результат сохраняется в мета-таблицу `pools_meta.parquet` и шардированное Parquet-хранилище связей `(pool_id, post_id)` с шардированием `pool_shard = pool_id // 1000`.

## 3. Оценка семантической чистоты через энтропию (`step_pools_entropy`)

Пулы делятся на две категории:
- `series`: упорядоченные истории (комиксы, манга, покадровые наборы). Обладают высокой тематической связностью.
- `collection`: произвольные пользовательские закладки. Могут быть как высокотематическими (например, «только красные драконы»), так и энтропийным мусором («все арты, которые мне понравились за 5 лет»).

### 3.1. Шенноновская энтропия распределения тегов
Для каждого пула вычисляется распределение вероятностей встретить тег $t$:
$$p(t) = \frac{\mathrm{cnt}(t)}{\sum_{j} \mathrm{cnt}(j)}$$
Классическая информационная энтропия тегов:
$$H_{\mathrm{tags}} = - \sum_{t} p(t) \ln p(t)$$

### 3.2. IDF-взвешенная энтропия
Чтобы частые стоп-теги не искажали энтропию, вычисляется модифицированная энтропия с весами IDF:
$$w(t) = \mathrm{cnt}(t) \cdot \mathrm{IDF}(t), \quad p_w(t) = \frac{w(t)}{\sum_{j} w(j)}$$
$$H_{\mathrm{idf}} = - \sum_{t} p_w(t) \ln p_w(t)$$

### 3.3. Маска валидности (`_eligible_pools_mask`)
Пул допускается к генерации графов тогда и только тогда, когда выполняются условия, заданные флагами `cfg.pools_use_series` и `cfg.pools_use_collections`:
$$\text{Eligible} = (\text{category} == \text{"series"} \;\land\; \text{use\_series}) \;\lor\; \Big(\text{category} == \text{"collection"} \;\land\; \text{use\_collections} \;\land\; \text{score} \le \mathrm{entropy\_max}\Big)$$
Где $\text{score}$ — это $H_{\mathrm{idf}}$ при его наличии, либо $H_{\mathrm{tags}}$, если метрика IDF недоступна. Порог `pools_collection_entropy_max` (5.5–6.0) отсекает хаотичные коллекции.

## 4. Взвешенный граф постов (`step_pool_edges`)
Для каждого валидного пула размером $n$ между всеми парами постов $(a, b)$ генерируется ребро. Вес ребра убывает с ростом размера пула, отражая закон убывающей специфичности:
$$w(a, b) = \frac{1}{\sqrt{n}}$$
Если два поста входят вместе в несколько различных пулов, их веса суммируются:
$$W_{\mathrm{total}}(a, b) = \sum_{p \in \mathrm{Pools}(a, b)} \frac{1}{\sqrt{|p|}}$$
Результат пишется в `pool_edges.parquet` (`[a_post_id, b_post_id, weight, pools]`).

## 5. Mmap участия постов в пулах (`step_post_in_pools_count`)
Подсчитывает, в скольких валидных пулах состоит каждый пост базы. Записывается в бинарный файл `mmaps/post_in_pools_count.bin` (тип `int32`), строго выровненный относительно массива `mmaps/post_ids.bin`. Используется в поисковом ранжировании как признак ценности публикации.

## 6. Со-встречаемость тегов из пулов (`step_pool_tag_co`)
Пулы объединяют посты одной темы, даже если на отдельных картинках авторы забыли проставить важные теги.
1. В каждом пуле отбираются топ $M$ тегов (по умолчанию 24, настраивается через `cfg.pools_top_tags`) с максимальным суммарным весом $\mathrm{cnt}(t) \cdot \mathrm{IDF}(t)$, либо по сырому $\mathrm{cnt}(t)$, если IDF недоступен.
2. Для каждой пары тегов генерируется ребро с весом $1 / \sqrt{|pool|}$, где $|pool|$ — размер пула в постах (извлекается из `size_map`), с откатом к $n_{\mathrm{tags}}$ (размеру списка тегов), если размер неизвестен.
3. Результат сохраняется в `tag_co_from_pools.parquet`. Данный граф подается на вход модели `tag2vec_stage.py` для обогащения PMI-матрицы глобальным контекстом.
