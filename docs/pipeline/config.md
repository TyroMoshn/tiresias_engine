# Модуль `config.py` (Техническая документация)

## 1. Назначение и Архитектурная роль
Модуль `config.py` определяет центральную структуру конфигурации пайплайна индексации данных — датакласс `Config`. Он инкапсулирует:
- Физические пути к исходным данным (CSV), промежуточным партиционированным хранилищам (Parquet) и целевым бинарным индексам (Roaring Bitmaps, Memory-Mapped файлы, упакованные Top-K списки).
- Гиперпараметры ETL-стадий (размеры шардов, пороговые значения фильтрации, размеры батчей).
- Гиперпараметры статистических моделей и алгоритмов машинного обучения (размерность векторов Tag2Vec, минимальная частота документов, окно контекста PMI, пороги энтропии пулов).

Класс является де-факто единым контрактом (single source of truth) для всех шагов пайплайна (`io_stage`, `tags_stage`, `index_stage`, `stats_stage`, `pools_stage`, `tag2vec_stage`, `post2vec_stage`).

### 2.2. Параметры партиционирования и ETL
- `tag_shards: int = 256`: Количество шардов/файлов для партиционирования связей постов и тегов (вычисляется как `tag_id % tag_shards`).
- `parquet_row_group_rows: int = 1_000_000`: Размер Row Group при потоковой записи Parquet (оптимизация I/O при чтении).
- `workers: int = os.cpu_count() or 4`: Пул параллельных потоков/процессов для DuckDB, ThreadPoolExecutor и Polars.
- `force: bool = False`: Флаг принудительной перезаписи артефактов без проверки `newer_than`.
- `reliable_only: bool = True`: Глобальный фильтр для исключения удаленных (`is_deleted`) и находящихся на модерации (`is_pending`) постов.

### 2.3. Параметры пулов (Pools Stage)
- `pool_min_size: int = 3`, `pool_max_size: int = 200`: Границы валидного размера пула для исключения шума и огромных коллекций.
- `pools_use_series: bool = True`, `pools_use_collections: bool = True`: Включение пулов типов `series` и `collection`.
- `pools_collection_entropy_max: float = 6.0`: Максимальная энтропия тегов коллекции (отсекает бессвязные свалки разнородных картинок).
- `pools_top_tags: int = 24`: Количество доминирующих тегов, извлекаемых из пула для расчета со-встречаемости.

### 2.4. Параметры Top-K и IDF
- `topk_k: int = 5000`: Максимальная глубина списка Top-K постов для одного тега.
- `topk_mode: str = "static"`: Режим выборки (`static` — фиксированное число $K$, `sqrt_df` — динамическое $K \propto \beta \sqrt{\mathrm{DF}}$).
- `topk_k_min: int = 100`, `topk_k_max: int = 5000`, `topk_beta: float = 10.0`: Параметры динамического Top-K.
- `idf_alpha: float = 1_000.0`: Сглаживающий аддитивный параметр в формуле IDF: $\log\frac{N + \alpha}{\mathrm{DF} + \alpha}$.
- `idf_source: str = "auto"`: Режим расчета частоты документов (`tags` из `tags.csv`, `local` по реальным постам, `auto` по корреляции Пирсона).
- `idf_auto_switch_threshold: float = 0.90`: Порог корреляции, ниже которого `auto` переключается на локальный расчет.

### 2.5. Параметры PMI и Графа Импликаций
- `pmi_support: int = 50`: Минимальный порог абсолютной совместной встречаемости тегов для сохранения ребра PMI.
- `pmi_top_m_per_post: int = 16`: Ограничение числа наименее частотных тегов на один пост при построении матрицы со-встречаемости.
- `anc_cache_depth: int = 3`: Глубина транзитивного замыкания графа предков в кэше.
- `anc_cache_top_percent: float = 0.05`: Доля наиболее популярных тегов, для которых строится транзитивный кэш предков.

### 2.6. Параметры Tag2Vec и Roaring
- `tag2vec_dim: int = 128`: Размерность векторного пространства тегов.
- `tag2vec_min_df: int = 100`: Минимальная частотность тега для включения в словарь эмбеддингов.
- `tag2vec_max_tags: int = 200_000`: Максимальный размер словаря тегов.
- `tag2vec_source: str = "merge"`: Источник весов графа (`merge` — смесь PMI и пулов, `pmi`, `pools`).
- `tag2vec_pool_alpha: float = 0.5`: Коэффициент масштабирования весов из пулов при смешивании: $W = W_{\mathrm{pmi}} + \alpha W_{\mathrm{pools}}$.
- `tag2vec_shift: float = 0.0`: Постоянный сдвиг в формуле PPMI ($\max(0, \mathrm{PMI} - \text{shift})$).
- `tag2vec_knn_k: int = 32`: Количество ближайших соседей при расчете k-NN графа.
- `roar_shard_size: int = 0`: Размер шардирования при записи битмапов в устаревшем режиме.

### 2.7. Параметры Post2Vec v2 и категориальные веса
- `post2vec_index_sq8: bool = True`: Построение скалярно-квантованного индекса FAISS SQ8 (630 МБ вместо 2.6 ГБ).
- `post2vec_batch: int = 200_000`: Размер батча при построении векторов.
- `category_weights: Dict[int, float]`: Словарь весовых коэффициентов для взвешивания тегов по их типу (`category`):
  - `1` (Artist): `2.5`
  - `4` (Character): `2.0`
  - `3` (Copyright): `1.8`
  - `5` (Species): `1.30`
  - `0` (General): `1.0`
  - `7` (Meta): `0.05`
  - `2` (Contributor): `0.00`
  - `6` (Invalid): `0.00`
  - `8` (Lore): `0.00`

### 2.8. Параметры коллаборативной фильтрации (Collab Stage)
- `fav_user_min_posts: int = 3`: Минимальное количество лайков пользователя.
- `fav_user_max_posts: int = 500`: Максимальное количество лайков пользователя (отсечение ботов).
- `cofav_min_weight: float = 0.5`: Минимальный порог веса связи со-лайков для сохранения в граф.
- `cofav_max_edges_per_post: int = 64`: Максимальное число исходящих рёбер на один пост.
- `taste_archetypes_k: int = 64`: Количество кластеров вкусовых архетипов при `MiniBatchKMeans`.
- `taste_archetypes_top_posts: int = 500`: Количество репрезентативных постов, сохраняемых на каждый архетип.

## 3. Кроссплатформенное разрешение путей (`get_default_data_root`)
Функция `get_default_data_root()` реализует универсальное определение корневой директории данных:
1. При наличии переменной окружения `TIRESIAS_DATA_ROOT` берется указанный путь.
2. При ее отсутствии автоматически вычисляется папка `data` рядом с корнем проекта:
Это обеспечивает бесшовный запуск конвейера в любой операционной системе (Windows, Linux) независимо от расположения папки.

## 4. Методы
- `__post_init__(self) -> None`: Выполняет автоматическое разрешение (фоллбэк) путей для опциональных полей (например, `uploaders_csv`, `user_favorites_csv`), если они не были явно заданы.
- `to_json(self) -> str`: Сериализует текущую конфигурацию в человекочитаемый форматированный JSON со строковыми путями для аудита и логирования в консоль.
