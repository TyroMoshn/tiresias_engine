# Модуль `stats_stage.py` (Техническая документация)

## 1. Назначение и Архитектурная роль
Модуль `stats_stage.py` отвечает за статистический анализ корпуса данных, расчет метрик информационной ценности тегов, вычисление матрицы совместной встречаемости и предварительную сериализацию списков популярного контента:
1. `step_tag_stats`: Расчет сглаженной обратной частоты документов (IDF), средней оценки (`avg_score`), среднего числа лайков (`avg_fav`) и локальной частотности документов (`df_local`).
2. `step_pmi`: Построение разреженной матрицы со-встречаемости тегов в публикациях и расчет метрики точечной взаимной информации (PMI — Pointwise Mutual Information).
3. `step_topk`: Расчет и упаковка списков Top-K лучших публикаций по каждому тегу с использованием дельта-кодирования (D-gaps) и Variable Byte (Varint).

## 2. Расчет IDF и популярности (`step_tag_stats`)

### 2.1. Формула сглаженного IDF
Для балансировки весов тегов в последующих векторных моделях (Post2Vec) вычисляется сглаженная инверсная частота документа (Smoothed IDF):
$$\mathrm{IDF}(t) = \log \left( \frac{N_{\mathrm{posts}} + \alpha}{\mathrm{DF}(t) + \alpha} \right)$$
где $\alpha = 1\,000.0$ (`cfg.idf_alpha`) — аддитивный гиперпараметр сглаживания, предотвращающий завышение веса у экстремально редких тегов с опечатками.

### 2.2. Автоматический выбор источника частотности (`idf_source="auto"`)
В наборе данных присутствуют две оценки частотности:
- `post_count` из глобального `tags.csv` (может быть устаревшим или отражать базу до удаления постов).
- `df_local`, рассчитанный непосредственно по неудаленным строкам в `posts_parquet`.

Алгоритм вычисляет коэффициент корреляции Пирсона для топ 1% тегов в логарифмической шкале:
$$r = \mathrm{corr}\big(\log(1 + \mathrm{post\_count}),\; \log(1 + \mathrm{df\_local})\big)$$
Если $r < \text{idf\_auto\_switch\_threshold}$ (0.90), система автоматически переключается на использование локальной частоты `df_local`.

Результат сохраняется в `tags.parquet`.

## 3. Матрица взаимной информации тегов (`step_pmi`)

### 3.1. Фильтрация частотных стоп-тегов
В каждом посте присутствует большое число служебных и тривиальных тегов (например, `solo`, `monochrome`), создающих шумовые связи со всеми остальными тегами. Для подавления шума применяется эвристика:
- Для каждого поста отбираются не более $M = 16$ (`cfg.pmi_top_m_per_post`) **наименее частотных** тегов (минимальный `post_count`).

### 3.2. Векторизованный расчет со-встречаемости через разреженные матрицы
1. Строится разреженная бинарная матрица инцидентности $X \in \{0, 1\}^{N \times T}$ в формате CSR (`scipy.sparse.csr_matrix`), где $N$ — число постов, $T$ — уникальные теги.
2. Матрица ко-инцидентности вычисляется через транспонированное матричное произведение:
   $$C = X^T X \in \mathbb{N}_0^{T \times T}$$
3. Диагональ зануляется: $C_{ii} = 0$.
4. Оставляются только пары с верхнего треугольника ($i < j$), удовлетворяющие порогу статистической поддержки: $C_{ij} \ge \mathrm{pmi\_support}$ (по умолчанию 50).

### 3.3. Расчет метрики PMI
Для отобранных пар вычисляются маргинальные и совместные вероятности:
$$P(a) = \frac{\text{cnt}_a}{N}, \quad P(b) = \frac{\text{cnt}_b}{N}, \quad P(a, b) = \frac{C_{ab}}{N}$$
$$\mathrm{PMI}(a, b) = \log \left( \frac{P(a, b) + \varepsilon}{P(a) P(b) + \varepsilon} \right), \quad \varepsilon = 10^{-12}$$

Результат выгружается в `tag_pmi.parquet` с колонками `[a, b, support, pmi]`.

## 4. Расчет и упаковка Top-K (`step_topk`)

### 4.1. Ранжирование постов
Посты внутри каждого тега сортируются по компаратору качества:
$$\text{ORDER BY } \mathrm{fav\_count} \text{ DESC},\; \mathrm{score} \text{ DESC},\; \mathrm{post\_id} \text{ DESC}$$

### 4.2. Режимы выборки глубины $K$
1. **Режим `static`**: фиксируется ровно $K = \text{cfg.topk\_k}$ (5000 постов).
2. **Режим `sqrt_df`**: динамический размер в зависимости от популярности тега:
   $$K(t) = \text{clip}\Big(\big\lceil \beta \cdot \sqrt{\mathrm{DF}(t)} \big\rceil,\; K_{\min},\; K_{\max}\Big)$$
   где $\beta = 10.0, K_{\min} = 100, K_{\max} = 5000$.

### 4.3. Пошаговая обработка шардов (Shard-by-Shard Memory Optimization)
Для предотвращения накопления всех 258 млн связей пост-тег в памяти, `step_topk` обрабатывает датасет строго пошагово по 256 шардам:
- Каждый шард считывает только свой фрагмент данных (~1 млн строк, ~50 МБ RAM).
- Внутри шарда выполняется группировка, сортировка по качеству и срез Top-K.
- Отобранные идентификаторы постов сортируются по возрастанию для применения D-gap сжатия.
- Список сжимается функцией `encode_varint_delta` (дельта между соседними ID кодируется переменной длиной байт).
- Сжатый блоб записывается в файл шарда `shard_XXXX.topkpack` (где шард $\text{tag\_id} \pmod{\text{tag\_shards}}$).
- В `index_XXXX.bin` заносится 16-байтовая запись `<iqi` (`tag_id`, `offset`, `length`).
- Память освобождается сборщиком мусора перед переходом к следующему шарду. Пиковое потребление RAM удерживается $< 400$ МБ.

Позволяет поисковой выдаче мгновенно отдавать готовую ленту лучших картинок по любому тегу с минимальным дисковым I/O.
