# Модуль `graphs.py` (Техническая документация)

## 1. Назначение
Модуль `graphs.py` реализует классический алгоритм Тарьяна (Tarjan's Strongly Connected Components algorithm) для поиска компонент сильной связности (SCC) в ориентированных графах со строковыми вершинами.

В пайплайне этот алгоритм используется в `tags_stage.py`:
1. **При обработке синонимов (алиасов тегов)**: для обнаружения циклов перенаправлений (например, $A \to B \to C \to A$) и их стягивания в единый канонический тег с максимальной популярностью.
2. **При обработке импликаций (иерархий тегов)**: для поиска циклов в графе иерархии ($A \implies B \implies A$) и превращения ориентированного графа в бесконтурный ориентированный граф (DAG — Directed Acyclic Graph).

## 2. Математическое описание и алгоритм Тарьяна

### 2.1. Постановка задачи
Пусть задан ориентированный граф $G = (V, E)$, где $V$ — множество строковых идентификаторов тегов, а $E \subseteq V \times V$ — ориентированные ребра.
Подграф $C \subseteq V$ называется **компонентой сильной связности**, если для любых двух вершин $u, v \in C$ существует ориентированный путь из $u$ в $v$ и из $v$ в $u$.

### 2.2. Реализация функции `tarjan_scc` (Итеративная версия)
```python
def tarjan_scc(nodes: List[str], edges: Dict[str, List[str]]) -> List[List[str]]:
```

Алгоритм выполняет поиск в глубину (DFS) с поддержкой вспомогательных структур:
- `idx[v]`: Порядковый номер (индекс входа) вершины $v$ в обходе DFS.
- `low[v]`: Наименьший индекс вершины, достижимой из $v$ через потомков в дереве DFS и не более одного обратного ребра в текущем стеке.
- `stack`: Стек вершин, находящихся в процессе обработки текущей компоненты.
- `onstack`: Множество для проверки принадлежности вершины стеку за $O(1)$.
- `call_stack`: Явный стек вызовов Python `[(vertex, outgoing_neighbors, current_neighbor_index)]`, эмулирующий рекурсию в куче (heap) с кэшированием списка соседей.

#### Ход итеративного алгоритма:
1. Инициализируется глобальный счетчик `index = 0`.
2. Для каждой непосещенной вершины создается фрейм в `call_stack`:
   - При входе в вершину $v$: присваивается `idx[v] = low[v] = index++`, вершина помещается в `stack` и `onstack`.
   - На каждом шаге цикла извлекается вершина, список ее соседей и текущий индекс соседа $(u, \text{neighbors}, i)$.
   - Если есть непосещенный сосед $w$: индекс соседа инкрементируется, вершина $w$ пушится на стек вызовов (переход вглубь без вызова функций Python).
   - Если сосед $w$ уже в стеке: `low[v] = min(low[v], idx[w])`.
   - При возврате из поддерева соседа $w$: `low[v] = min(low[v], low[w])`.
3. Если после обхода всех соседей $low[v] == idx[v]$, вершина $v$ является корнем компоненты:
   - Из стека извлекаются все элементы до $v$ включительно — они формируют очередную компоненту связности (`comp`).
   - Компонента добавляется в список результатов `sccs`.

## 3. Вычислительная сложность и устойчивость к переполнению стека
- **Временная сложность**: $O(|V| + |E|)$, так как каждая вершина и каждое ребро просматриваются строго фиксированное число раз.
- **Пространственная сложность**: $O(|V| + |E|)$ для хранения структур `idx`, `low`, графа `edges` и стека обхода.
- **Защита от переполнения стека (Anti-Recursion Safety)**:
  В отличие от стандартной рекурсивной реализации, итеративный алгоритм **не использует стек вызовов CPython**. Он способен без модификации `sys.setrecursionlimit` и риска `RecursionError` / `Stack Overflow` корректно обрабатывать ориентированные цепочки глубиной более $150\,000$ вершин менее чем за $0.6$ секунды.
