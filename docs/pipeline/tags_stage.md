# Модуль `tags_stage.py` (Техническая документация)

## 1. Назначение и Архитектурная роль
Модуль `tags_stage.py` выполняет нормализацию текстовых тегов, разрешение графов синонимов (алиасов), построение шардированного индекса связей «публикация — тег» (`post_tags_parquet`), а также построение бесконтурного ориентированного графа иерархий тегов (DAG импликаций) с кэшем предков.

Модуль состоит из двух ключевых шагов:
1. `step_tags_and_post_tags`: Денормализация строки тегов постов, подстановка канонических синонимов, маппинг в целочисленные `tag_id` и шардирование по `cfg.tag_shards` корзинам (по умолчанию 256).
2. `step_implications`: Преобразование графа импликаций в DAG и расчет префиксного транзитивного кэша предков.

## 2. Разрешение графа синонимов (`build_alias_map`)

Пользовательские синонимы задаются парами: $\text{antecedent\_name} \to \text{consequent\_name}$. В реальных данных присутствуют:
- Длинные транзитивные цепочки: $A \to B \to C \to D$.
- Циклические зависимости: $A \to B \to A$.

### Алгоритм разрешения:
1. **Построение ориентированного графа**: ребра образуют словарь `next_of: A -> B`.
2. **Поиск компонент сильной связности (SCC)**: вызывается `tarjan_scc` из `graphs.py`.
3. **Выбор канонического представителя**:
   Для каждой компоненты связности выбирается вершина с максимальным числом использований на сайте (`post_count` из `tags.csv`):
   $$\text{best} = \arg\max_{v \in \text{comp}} (\mathrm{post\_count}(v), -v)$$
4. **Сжатие путей (Path Compression)**:
   Функция `compress(name)` обходит граф вперед по указателям до достижения терминальной вершины либо цикла, возвращая канонический идентификатор:
   $$\mathrm{alias\_map}[a] = \text{compress}(b)$$

## 3. Этап `step_tags_and_post_tags`

### 3.1. Конвейер обработки
1. Фильтрация постов: если включен `cfg.reliable_only`, посты с `is_deleted == True` или `is_pending == True` исключаются.
2. Векторизованный сплит строки: колонка `tag_string` («tag1 tag2 tag3») разбивается в массив строк и разворачивается через `explode("tags")`.
3. Применение карты алиасов: имена тегов заменяются каноническими через Polars `replace(alias_map)`.
4. Дедупликация: внутри каждой публикации устраняются дубликаты `unique(subset=["post_id", "tag"])`.
5. Left Join со словарем тегов `tags_lookup` и последующий `drop_nulls`: строковый тег заменяется на компактный 32-битный суррогатный ключ `tag_id`.

### 3.2. Хэш-шардирование связей
Связи распределяются по `cfg.tag_shards` корзинам по остатку от деления:
$$\mathrm{tag\_shard} = \mathrm{tag\_id} \pmod{\mathrm{cfg.tag\_shards}}$$
Для каждого шарда выделяется постоянный экземпляр `pyarrow.parquet.ParquetWriter`, в который блоками по `parquet_row_group_rows` (по умолчанию 1 000 000 строк) дописываются таблицы со схемой:
- `post_id: Int64`
- `tag_id: Int32`

Сжатие: Zstandard (`zstd`).

### 3.3. Фильтрация словаря тегов
На выходе формируется компактный словарь `tags_dict.parquet`, содержащий только те теги, которые встретились хотя бы в одной неудаленной публикации.

## 4. Этап `step_implications` (Иерархии и Кэш Предков)

Импликация декларирует семантическое отношение «частное $\implies$ общее» (например, `husky` $\implies$ `dog` $\implies$ `animal`).

### 4.1. Построение DAG импликаций (`tag_implications.parquet`)
1. Подстановка канонических синонимов через `alias_map` для обоих концов ребра.
2. Удаление петель вида $A \implies A$.
3. Устранение циклов: алгоритм Тарьяна разбивает граф на компоненты связности `comp_id`. Ребра между вершинами одной и той же компоненты отбрасываются ($\mathrm{comp\_id}[a] \neq \mathrm{comp\_id}[b]$). Граф гарантированно становится бесконтурным (DAG).
4. Результирующие ребра сохраняются в `tag_implications.parquet` со схемой `(a_id: Int64, b_id: Int64)`.

### 4.2. Транзитивный кэш предков (`tag_ancestors_cache.parquet`)
Полнотекстовый поиск с разворачиванием дерева родителей в рантайме накладен. Поэтому для наиболее высоконагруженных тегов (топ 5% по `post_count`) строится статический кэш:
- Выполняется поиск в ширину (BFS) по графу смежности на глубину `anc_cache_depth = 3`.
- Сохраняются кортежи `(tag_id: Int32, ancestor_id: Int32, depth: Int8)`.
- Позволяет поисковому движку за одно чтение индекса расширять запрос пользователя всеми его логическими предками.
