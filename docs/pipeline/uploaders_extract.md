# Модуль `uploaders_extract.py` (Техническая документация)

## 1. Назначение и Контекст
Модуль `uploaders_extract.py` представляет собой автономную утилиту предварительной обработки данных (Data Ingestion Utility). Он извлекает из основного дампа `posts_parquet` (или `posts.csv` как фоллбэк) атрибуты авторства загрузки (`id`, `uploader_id`) и агрегирует их в производный датасет `uploaders_uploads.csv`.

Формат выходного файла полностью унифицирован со схемой таблицы пользовательского избранного `user_favorites.csv`:
$$\text{user\_id (int)}, \quad \text{upload\_count (int)}, \quad \text{uploads (string "\{id,id,...\}")}$$

Сортировка выходных записей выполняется по количеству загрузок (`upload_count`) по возрастанию.

## 2. Архитектурные особенности реализации

### 2.1. Использование высокопроизводительных движков обработки
Скрипт использует современные OLAP-движки для достижения максимальной пропускной способности при обработке гигабайтов данных:
- **DuckDB**: используется по умолчанию, применяет векторизованный SQL-запрос с агрегацией `string_agg` и прямым экспортом в CSV через команду `COPY`.
- **Polars**: используется в качестве fallback-механизма (в случае ошибки DuckDB), применяет потоковое API (`streaming`) для агрегации списков.
- Поддерживает многопоточность: DuckDB конфигурируется с директивой `PRAGMA threads={workers}`, а Polars применяет внутренний параллелизм.

### 2.2. Интеграция с пайплайном и инкрементальное обновление
Скрипт интегрирован в основной пайплайн через функцию `step_uploaders_extract(cfg: Config)`:
- Задействует общие модули проекта: `Config`, `log`, `ensure_dir`, `newer_than`.
- Инкрементальное выполнение (кэширование): если результирующий CSV существует и он новее исходного Parquet (или CSV), пересчет пропускается (кроме случая использования флага `--force`).

## 3. Интерфейс командной строки (CLI)
Скрипт можно запускать автономно. Доступные параметры:
- `--root`: корневая директория с данными.
- `--csv`: путь к исходному файлу `posts.csv`.
- `--out`: путь к результирующему файлу.
- `--workers`: число потоков (по умолчанию 4).
- `--force`: принудительный пересчет, игнорируя кэширование.
