# Модуль `autotest/autotest_index.py` (Техническая документация)

## 1. Назначение и Архитектурная роль
Модуль `autotest_index.py` представляет собой сквозной валидационный комплекс (Automated Data Quality & Integrity Test Suite). Его цель — верификация физической корректности, целостности схем данных, отсутствия бинарных повреждений и согласованности между различными представлениями одних и тех же сущностей в выходных артефактах пайплайна.

Модуль выдает консольный отчет со статусами `PASS`, `FAIL`, `WARN`, `SKIP`, сохраняет отчет `autotest_report.txt` и генерирует криптографический манифест контрольных сумм `autotest_manifest.json` на основе алгоритмов **xxHash (XXH3_128)** или **BLAKE2b**.

## 2. Набор проверок (Test Suite)

### 2.1. Валидация схемы и партиций `posts_parquet` (`check_posts_parquet_schema`)
- Сканирует структуру каталогов `posts_parquet/`.
- Проверяет наличие всех 31 ожидаемых колонок.
- Поддерживает автоматическое распознавание Hive-партиционирования: распознает ключи партиций (`rating`, `year`, `month`) из структуры каталогов, даже если они физически исключены из бинарных данных Parquet.
- Валидирует низкоуровневые типы PyArrow/Polars: `id` как `Int64`, `created_at` как `Datetime`, флаги `is_deleted`/`is_pending` как `Boolean`/`UInt8`.

### 2.2. Валидация шардов связей `post_tags_parquet` (`check_post_tags_schema`)
- Проверяет наличие партиций `tag_shard=*`. (Не валидирует наличие всех 256 шардов, а проверяет выборку до 5 шардов, либо 2 в режиме `--quick`).
- Проверяет точное совпадение колонок `[post_id, tag_id]` и их числовых типов.
- Проводит проверку на отсутствие дубликатов пар `(post_id, tag_id)` внутри файлов шарда.

### 2.3. Целостность словаря `tags_dict.parquet` (`check_tags_dict`)
- Проверяет схему `[tag_id, tag, category, post_count]`.
- Проверяет типы числовых колонок (Int32/Int64).

### 2.4. Выравнивание Memory-Mapped массивов (`check_mmaps`)
- Проверяет наличие обязательных бинарных файлов: `post_ids.bin`, `epoch_day.bin`, `w.bin`, `h.bin`, `score.bin`, `fav_count.bin`, `is_deleted.bin`, `is_pending.bin`.
- **Строгое выравнивание длины (Dimensional Alignment)**: размер каждого бинарного массива (с учетом размера элемента типа `int32`, `int64` или `uint8`) должен строго равняться длине опорного массива `post_ids.bin` ($N$).
- **Монотонность первичного ключа**: проверяет вектор разностей $\Delta = \text{diff}(\mathrm{post\_ids})$. Все элементы должны строго удовлетворять условию $\Delta_i > 0$ (строгое возрастание без дублей и нарушений сортировки).
- Проверяет опциональный массив участия в пулах `post_in_pools_count.bin`.

### 2.5. Проверка ортогональности масок рейтинга (`check_rating_roars`)
- Читает и десериализует `rating_s.roar`, `rating_q.roar`, `rating_e.roar`.
- **Попарное непересечение (Disjointness)**:
  $$|S \cap Q| = 0, \quad |S \cap E| = 0, \quad |Q \cap E| = 0$$
- **Полнота покрытия (Exhaustiveness)**:
  $$|S \cup Q \cup E| == N_{\mathrm{posts\_parquet}}$$
  (проверяется прямым агрегатным запросом `COUNT(*)` через движок DuckDB по партициям Parquet).

### 2.6. Верификация Roaring-индексов тегов (`check_tag_bitmaps_against_post_tags`)
- Поддерживает как легаси-режим отдельных файлов (`tag_*.roar`), так и пакетный режим (`shard_*.roarpack` + `index_*.bin`).
- Проверяет корректность 16-байтовых заголовков `<iqi` в индексе: смещение не должно быть отрицательным, длина блоба больше нуля, диапазон `[offset, offset + length]` не выходит за физический размер `.roarpack`.
- Десериализует Roaring Bitmap для случайного тега и сопоставляет его содержимое с эталонным результатом аналитического сканирования Parquet-шардов `post_tags_parquet`. Множества ID обязаны совпадать побитово.

### 2.7. Проверка Top-K архивов (`check_topk`)
- Проверяет структуру пакетов `shard_*.topkpack` и индексов `index_*.bin`.
- Распаковывает бинарные байты через дельта-декодер Varint:
  $$x_i = x_{i-1} + \Delta_i$$
- Проверяет инвариант строгой монотонности распакованного списка постов: $x_i < x_{i+1}$.
- Сравнивает распакованный Top-K с эталонным пересчетом постов из Parquet (фильтруя удаленные и ожидающие модерации) по формуле `ORDER BY fav_count DESC, score DESC, post_id DESC`. Проверяется, что распакованный список является надмножеством для эталонного Top-K (subset verification).

### 2.8. Проверка структур пулов (`check_pools`)
- Проверяет наличие и схему `pools_meta.parquet`, `pools_parquet` и `pool_entropy.parquet`.
- Валидирует, что энтропия тегов в пулах корректно рассчитана и строго положительна.
- Опционально проверяет схемы и положительность весов в `pool_edges.parquet` и `tag_co_from_pools.parquet`.

### 2.9. Сверка Parquet с исходным CSV (`check_against_csv`)
- Сверяет количество строк, сумму и границы `id` между `posts.csv` и `posts_parquet`, используя DuckDB.

### 2.10. Профилирование производительности (`perf_profile`)
- Измеряет время открытия memory-mapped массивов и стоимость случайной выборки (slicing).
- Замеряет скорость десериализации Roaring Bitmap.
- Замеряет скорость агрегации количества строк в `post_tags_parquet`.

## 3. CLI интерфейс и параметры
```bash
python autotest_index.py \
    --root "data" \
    --report "autotest_report.txt" \
    --manifest "autotest_manifest.json" \
    --sample-tags 10 \
    --k-cap 1000 \
    --quick
```
- `--quick`: экспресс-тестирование на малых сэмплах данных.
- `--sample-tags`: количество тегов для глубокой перекрестной валидации.
- `--emit-bat`: генерация готового Windows-батника для автоматического запуска (целое число, по умолчанию `1`).
